# 项目定位与范围

本文档定义 `vxmq` 的长期项目定位、范围边界和演进原则。当前阶段、能力完成度和下一步优先级统一查看 [`../01-status/current-status.md`](../01-status/current-status.md) 与 [`../01-status/roadmap.md`](../01-status/roadmap.md)。

## 项目目标

- 构建一个严格遵循 MQTT 协议、同时支持 MQTT 3.1.1 与 MQTT 5 的 Java Broker。
- 以 Quarkus + Mutiny + Vert.x 为宿主，建立清晰、可演进的单机 Broker 内核。
- 通过文档、ADR、自动化测试和阶段验收形成长期可维护的工程基础。
- 让每个里程碑都能明确回答“已经支持什么、仍缺什么、下一步做什么”。

## 长期承诺范围

- Broker 本体能力，而不是 MQTT Client 或应用侧 SDK。
- 可验证的核心能力：
  - 连接管理
  - 发布订阅主链路
  - 会话状态
  - QoS 语义
  - Retained Message
  - Will Message
  - MQTT 5 关键属性
  - 鉴权与基础可观测性
- 围绕核心能力的自动化测试、阶段验收和设计决策留痕。

## 当前不在短期范围内

- 多节点集群与分布式一致性。
- 管理控制台、复杂管理 API 或完整运维平台。
- 大规模插件系统。
- 为未知生产场景做过度抽象。

## 长期不承诺范围

- 在没有明确产品需求前，把项目扩展成 IoT 平台、规则引擎或消息流处理平台。
- 为兼容个别客户端的非标准行为而牺牲协议正确性。
- 在缺少验证和文档前提下，以“先实现再解释”的方式引入大范围协议行为。

## 演进原则

- 规范优先于实现便利，状态清晰优先于功能堆积。
- 先完成可验证的最小闭环，再扩展高级能力与生产化能力。
- 新增范围必须明确协议依据、架构落点、测试要求和阶段归属。
- 文档、实现和验证必须一起演进，避免只在对话或代码里保存关键真相。
